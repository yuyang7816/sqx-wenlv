# 管理端功能说明

管理端是给平台工作人员用的网站，在电脑浏览器里打开。游客不使用这个网站。它用来看经营数字、审核商户、上下架内容、处理订单和提现，以及填写微信、支付宝、地图、公交、物流这些外面服务的账号。

工作人员登录后，左侧是菜单。能看到哪些菜单，由管理员给这个账号分配的权限决定。没有权限的菜单不会出现。

## 登录之后第一眼：数据统计

首页是「数据统计」。上面是今天的日期，下面是数字和图表。

**经营概况**

- 今日成交金额、本月成交金额
- 今日订单数、累计订单数

点这些数字会去「订单监管」。

**需要马上处理的事**

- 待处理订单
- 退款中的订单
- 等待审核的商户
- 今天新注册的用户

有待办时，页面上会出现提醒，例如「有几个商户入驻待审核」。点提醒直接去对应页面。

**已经上架的内容**

- 上架景区数量
- 精彩活动数量
- 入驻商户数量
- 注册用户数量

图表按最近一段时间画出成交趋势、订单分类、订单状态和用户情况。图表是网站自己画的，不连接外面的报表公司。订单分类包括酒店预订、旅游线路、非遗好物、商户服务、文创商品等。餐饮预约单独记账，不混进这张经营订单统计。

## 业务菜单里能管什么

### 首页配置

决定游客打开用户端首页时看到什么：

- 轮播大图：图片和点击后跳到哪里
- 快捷入口：例如「酒店住宿」「公共交通」这些图标，可以改名字、排序、隐藏
- 首页下方的推荐分类

改完保存后，用户下次打开首页就会变。这里不负责景区正文，正文在各自的管理菜单里。

### 景区、酒店、线路、活动、非遗

分别在这些菜单里维护，游客端有同名入口：

- **景区管理**：景区的介绍、图片、地址、是否上架。地址要用地图上的位置，游客才能导航。
- **酒店管理**：酒店资料。具体房间也可以由酒店商户在用户端自己的商户中心里维护，这里是平台侧查看和管理。
- **线路管理**：旅游线路的行程、价格、上下架。
- **活动管理**：精彩活动的时间、地点、介绍。
- **非遗管理**：非遗项目、非遗店铺、非遗商品。商品是可以填写收货地址、由商家发货的实物。

### 公告管理

写给游客看的通知。用户端首页那条滚动公告，以及「公告通知」「公告详情」，内容来自这里。

### 餐饮预约

查看和处理食堂、餐饮的预约记录，例如待确认的预约。这不是外卖平台对接，预约单存在自己的系统里。

### 订单监管

查看全平台订单：谁买的、哪一类（酒店、线路、商品等）、付了多少、现在是待处理、已支付还是退款中。

实物订单可以在这里查看物流。物流轨迹同样是先问阿里云快递查询，不行再问快递100。没配置时，只能看到商家填的公司和单号。

### 商户审核、商户管理、入驻类型

- **商户审核**：游客或商家在用户端提交入驻后，申请出现在这里。通过或拒绝。没通过之前，对方不能使用商户中心的经营功能。
- **商户管理**：查看已经入驻的店，看资料、状态。
- **入驻类型**：维护可以申请的店铺种类。系统自带四类：酒店、餐饮、旅游、文创。可以改名称，也可以新增类型。每种类型有一笔保证金金额，默认是按类型设置的（初始示例为 5000，以页面上保存的数字为准）。

商家在用户端上传的门头照、许可证，审核时在这里看。照片存在文件存储里（阿里云或服务器硬盘，见下文）。

### 优惠券模板

创建优惠券：谁可以领、减免多少。用户在「领券中心」领取，下单时选用。这里管的是券的规则，不是某一张已经发到个人手里的券。

### 邀请分销

查看谁邀请了谁。返佣比例、邀请海报、分享文案、分享链接在「平台配置」里改，不在这个列表里改文字。用户端「邀请好友」「我的团队」「收益明细」读的是这些结果。

佣金记在系统里。用户要提现时，再走提现审核，不会邀请成功就自动打到微信。

### 提现审核

分成两个标签：**用户提现**和**商户提现**。

每条记录能看到金额、状态（待审核、已通过、已驳回）、方式（支付宝或微信）。微信方式会看到对方上传的收款码图片；支付宝方式是对方填写的账号和姓名。

工作人员在这里点通过或驳回。通过表示平台同意打款，系统不会自动调用微信或支付宝把钱转走，打款仍要按页面上的账号或收款码人工处理。

### 支付监管

查看已经发生的付款记录，区分微信支付和支付宝，用来核对有没有付成功、金额对不对。真正扣款发生在用户付款的那一刻，这个页面是事后查看，不是在这里替用户付款。

### 意见反馈

用户在「意见反馈」里提交的内容出现在这里，供工作人员查看和处理。

### 消息管理

给用户发站内消息。用户在「消息」「消息详情」里看。这不是手机短信。短信要走「短信模板」和短信服务商。

### 在线聊天

工作人员在这里回复用户。用户从客服中心进入「在线客服」后，双方文字对话。对话存在自己的服务器上，通过网络长连接传递，不经过企业微信，也不经过微信客服会话。

如果平台配置里把默认客服改成了电话、微信二维码或企业微信，用户点客服时就不会进这个聊天窗。

## 平台配置：外面那些服务的开关都在这里

这是管理端和第三方关系最大的一页。页面说明是：维护产品名称、客服、协议、物流、微信支付、邀请分销、实时公交和提现规则。

### 品牌

产品名称。用户端登录页、页面标题，以及短信、邮件落款，都用这个名字。改完后用户端和管理端一起变。

### 客服

可以填：

- 客服电话
- 客服微信号
- 客服微信二维码图片
- 企业微信客服链接
- 企业微信的企业编号
- 默认使用哪一种：电话咨询、微信客服、企业微信、在线客服

另外有一个开关：**启用公众号支付**。打开之后，用户在微信里打开网页、并且是通过公众号登录的，预订和买东西时才能看到「微信支付」。关掉后，即使人在微信里，也不显示微信支付。

### 协议

用户服务协议、隐私政策、关于我们。用户端登录时勾选的两份协议，点开看的就是这里的正文。

### 提现规则

最低提现金额、最高提现金额、手续费比例。用户点提现时，金额必须落在这个范围里，手续费按这个比例算。

### 公共交通

两个设置：

- 是否启用实时公交
- apizero 的 API Key（向 apizero 申请的密钥）

打开并且密钥正确：用户端公共交通显示实时到站和车辆位置。关掉：用户端改看系统里保存的固定线路和时刻表。

### 订单抽成和线路退改

- 酒店订单平台抽成比例
- 线路订单平台抽成比例
- 线路在出行日前、出行当天、出行之后、未出现（No-show）分别扣多少
- 集合点保留到几点
- 给用户看的退改说明原文

这些数字决定一笔订单里平台留多少、商家留多少，以及用户取消时退多少。用户端只显示算好的结果。

### 物流

- 阿里云快递查询的 AppCode（阿里云市场里快递查询的通行证）
- 阿里云快递接口地址

快递100的账号如果要作为备用，配在系统配置里（客户编号和密钥）。用户查物流时，先用阿里云，查不到再用快递100。

### 微信支付

填写后，用户端才能拉起微信支付：

- 微信支付商户号
- 微信支付商户密钥
- 微信支付证书文件放在服务器的哪个路径
- 小程序的 AppId（登录和支付都会用到）
- 小程序支付用的 AppId
- 在微信网页里支付用的 AppId
- 网页支付组件用的 AppId

只把商户号填上、证书或 AppId 是空的，用户点微信支付仍然会失败。

支付宝的应用编号、私钥、公钥或证书，也要配在系统的支付配置里，支付监管页能看到支付宝是否已经配齐。管理端这个「微信支付」标签页本身不包含支付宝的输入框，支付宝是另一组配置。

### 邀请

邀请海报、复制文案、分享链接、一级和二级返佣怎么跟用户解释、一级和二级佣金比例。

## 用户和账号安全

- **C 端用户**：查看在用户端注册的人，例如手机号、昵称。这是游客和商户的登录账号，不是后台工作人员。
- **注销审核**：用户申请注销账号后，在这里审核。

## 系统管理：只给超级管理员一类的人用

- **管理员管理**：新增能登录这个网站的工作人员，设置初始账号。
- **角色管理**：例如「只看订单的人」「能审核商户的人」。
- **菜单管理、权限管理**：决定某个角色能看到哪些菜单、能点哪些按钮。
- **字典管理**：一些下拉选项的固定用词。
- **系统配置**：更细的开关和密钥，例如文件存到哪里、短信用哪一家、地图密钥、邮箱。平时优先用前面的「平台配置」；这里是同一套配置的完整列表。
- **操作日志**：谁在什么时间改了什么，用来事后核对。
- **短信模板**：验证码、通知短信的正文模板。真正把短信发出去的是短信服务商，模板要和那家服务商里申请的格式一致，否则手机会收不到。

## 管理端自己会连到哪些外面的服务

管理端大多是「把账号填进去」，真正打电话、收款、查地图发生在用户端和服务端。工作人员在这个网站上能直接碰到的外部服务是：

| 在管理端做的事 | 外面的服务 | 说明 |
|---|---|---|
| 上传轮播图、证件、商品图 | 阿里云对象存储，或服务器本机硬盘 | 由系统配置决定存哪里。选阿里云时，图片文件在阿里云上，页面上看到的是一个网址 |
| 看物流轨迹 | 阿里云快递查询、快递100 | 和用户看到的是同一条查询结果 |
| 打开在线聊天 | 自己的服务器 | 不是企业微信 |
| 图表 | 无 | 用网站自带的图表，数据来自自己的订单库 |

工作人员不要在这个网站里直接打开微信支付或支付宝去收款。收款发生在用户手机上。这里负责把商户号填对，并在「支付监管」里核对结果。
